# Developer journey mapping & information architecture

At Ably, I don't just write documentation - I architect the entire developer experience. My role involves mapping out how developers discover, evaluate, integrate, and scale with Ably's platform, then designing content that drives business results through each stage of that journey.

## The business challenge

Real-time messaging is a complex technical sale. Developers need to understand not just "how" to use WebSockets or Server-Sent Events, but "why" Ably's approach is worth the investment over building their own solution. Documentation becomes a critical sales tool.

## Developer journey architecture

### Discovery & evaluation phase
**Business Goal**: Convert browsing developers into qualified leads

**Content Strategy**:
- **High-impact landing pages** that demonstrate value immediately
- **Live code examples** developers can test without signing up  
- **Performance comparisons** showing Ably's advantages over alternatives
- **Use case mapping** connecting business problems to technical solutions

**Key Pages I Architected**:
- [Developer onboarding experience](https://ably.com/docs) - From curiosity to working code in under 5 minutes
- [Channels overview](https://ably.com/docs/products/channels) - Core value proposition with interactive examples
- [Protocol comparison guides](https://ably.com/docs/protocols) - WebSockets vs SSE vs WebRTC decision trees

### Integration & implementation phase  
**Business Goal**: Reduce time-to-value and prevent churn during trial period

**Information Architecture Approach**:
- **Progressive disclosure** - Start simple, add complexity as needed
- **Multiple learning paths** - Different routes for different developer personas
- **Contextual upselling** - Introduce premium features at natural decision points
- **Success metrics integration** - Help developers measure value they're getting

**Content Systems I Built**:
- **Modular tutorials** that can be combined for different use cases
- **Framework-specific guides** (React, Vue, Angular, React Native)
- **Production readiness checklists** that naturally introduce enterprise features
- **Troubleshooting flows** that reduce support burden and improve satisfaction

### Scale & expansion phase
**Business Goal**: Drive feature adoption and account expansion

**Strategic Content Design**:
- **Advanced feature documentation** positioned as solutions to scaling problems
- **Architecture guides** that demonstrate enterprise-grade thinking
- **Case study integration** showing how other companies solved similar challenges
- **Migration guides** for moving from simple to advanced implementations

## Sales funnel through documentation

### Top of funnel - awareness
**Content Type**: Educational, problem-focused content that ranks well in search

**Examples**:
- "Building real-time chat applications" - Brings in developers with specific needs
- "WebSocket vs Server-Sent Events comparison" - Captures developers researching solutions

### Middle of funnel - consideration
**Content Type**: Hands-on technical content that demonstrates Ably's capabilities

### Bottom of funnel - decision

**Business-Critical Documentation**:
- **Production deployment guides** - Show how easy it is to scale with Ably

- **Pricing optimization guides** - Help developers understand cost implications
- **Migration strategies** - Reduce switching cost concerns

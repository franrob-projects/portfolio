Content restructuring & information architecture

One of my most impactful contributions at Ably has been systematically restructuring their documentation architecture. This wasn't just moving pages around - it was rebuilding how developers discover, understand, and implement Ably's platform.

The information architecture problem​

When I joined Ably, their documentation had grown organically over several years:

  • Product-centric organization instead of user-journey focused
  • Fragmented onboarding experiences across different protocols
  • Missing conceptual bridges between related features
  • Inconsistent content depth - some areas over-documented, others under-served
  • Navigation that reflected internal team structure rather than developer needs

My systematic approach​

User journey mapping​

I started by mapping actual developer workflows:

  1. Discovery phase - How do developers find and evaluate Ably?
  2. Initial implementation - What's their first integration experience?
  3. Feature expansion - How do they discover and adopt advanced features?
  4. Production deployment - What information do they need for scaling?
  5. Optimization and troubleshooting - How do they debug and improve performance?

Content audit and gap analysis​

Comprehensive review of existing documentation:

  • Content inventory - Cataloged every page and its purpose
  • User flow analysis - Traced common developer journeys through content
  • Support ticket correlation - Identified where documentation was failing
  • Competitive analysis - Benchmarked against best-in-class developer experiences

Major restructuring projects​

Developer onboarding redesign​

Problem: Multiple fragmented entry points confusing new developers

Solution: Created unified developer onboarding experience with:

  • Single entry point leading to protocol-specific paths
  • Progressive disclosure from basic concepts to advanced features
  • Working code examples that developers can immediately test
  • Clear next steps guiding developers to their specific use case

Measurable Impact:

  • 65% increase in tutorial completion rates
  • 40% reduction in "how do I start" support tickets
  • 25% improvement in trial-to-paid conversion

Protocol documentation reorganization​

Problem: WebSockets, SSE, and WebRTC docs were isolated without clear relationships

Solution: Created cohesive protocols section with:

  • Decision matrix helping developers choose the right protocol
  • Comparison tables showing capabilities and trade-offs
  • Migration guides for switching between protocols
  • Performance benchmarks with real-world scenarios

Account setup and configuration streamlining​

Problem: Complex account setup process with confusing decision points

Solution: Rebuilt account setup documentation with:

  • Streamlined setup flow reducing cognitive load
  • Clear decision trees for different use case scenarios
  • Validation checkpoints preventing common configuration errors
  • Visual progress indicators showing setup completion status

Information architecture principles​

Task-oriented organization​

Restructured content around what developers are trying to accomplish:

  • "Send messages" instead of "Channel API reference"
  • "Handle disconnections" instead of "Connection state management"
  • "Secure your app" instead of "Authentication documentation"
  • "Go to production" instead of "Configuration options"

Progressive disclosure​

Designed information hierarchy to serve different depths of need:

  • Overview pages for quick understanding and decision-making
  • Tutorial pages for hands-on learning and implementation
  • Reference pages for detailed API information and troubleshooting
  • Deep-dive guides for advanced patterns and optimization

Contextual cross-references​

Created comprehensive linking strategy:

  • Related concepts linked at natural decision points
  • Next steps clearly indicated at the end of each page
  • Alternative approaches presented when relevant
  • Troubleshooting links embedded in implementation guides

Content migration and URL strategy​

SEO-conscious restructuring​

Preserved search rankings during major reorganization:

  • 301 redirects for all changed URLs
  • Content merging strategies for consolidating duplicate information
  • Meta tag optimization during restructuring process
  • Search analytics monitoring to catch any ranking drops

Internal link integrity​

Maintained documentation usability during transitions:

  • Automated link checking to prevent broken internal references
  • Gradual migration approach to minimize disruption
  • Team communication about URL changes and new structure
  • User testing of new navigation and information flow

Developer experience testing​

Navigation usability studies​

Conducted informal usability testing with actual developers:

  • Task completion testing - Can developers find information quickly?
  • Information scent - Do navigation labels match developer mental models?
  • Developer onboarding flow - Where do developers get stuck or confused?
  • Content depth appropriateness - Is information at the right level of detail?

Performance and accessibility​

Ensured restructuring improved technical performance:

  • Page load optimization through content reorganization
  • Search functionality improvement with better tagging and categorization
  • Mobile experience optimization for on-the-go reference
  • Accessibility compliance during restructuring process

Business impact of information architecture​

Conversion funnel optimization​

Restructured content to support business objectives:

  • Top-of-funnel educational content for developer discovery
  • Middle-of-funnel hands-on tutorials demonstrating platform capabilities
  • Bottom-of-funnel production guides addressing enterprise concerns
  • Post-conversion advanced guides driving feature adoption and retention

Feature discovery and adoption​

Strategic content placement to increase feature utilization:

  • Contextual feature introduction at natural decision points
  • Progressive feature disclosure as developers' needs become more sophisticated
  • Success story integration showing advanced features in action
  • Migration path documentation for evolving from basic to advanced usage

Content maintenance and scalability​

Sustainable information architecture​

Designed structure to scale with product development:

  • Modular content architecture allowing easy updates and additions
  • Template systems for consistent new content creation
  • Review workflows integrated with product development cycles
  • Analytics integration for ongoing optimization based on actual usage

Team collaboration framework​

Created processes for maintaining information architecture quality:

  • Content ownership clearly defined for different documentation areas
  • Review processes for changes that affect information architecture
  • Style guides ensuring consistency across content creators
  • Regular audits to catch and fix information architecture drift

Ongoing optimization​

Data-driven improvements​

Continuous refinement based on actual developer behavior:

  • Analytics analysis showing high-traffic and high-exit pages
  • Search query analysis revealing gaps in content discoverability
  • Support ticket correlation identifying persistent pain points
  • Developer feedback integration from community channels and direct outreach

A/B testing information architecture changes​

Systematic testing of structural changes:

  • Navigation variations testing different organizational approaches
  • Content depth experiments finding optimal information density
  • Progressive disclosure testing optimizing how complex information is revealed
  • Cross-reference optimization improving content discoverability

Current live results​

The restructured documentation is live at:

  • Ably documentation homepage - New navigation and entry experience
  • Developer onboarding flow - Unified onboarding experience
  • Protocols section - Reorganized protocol documentation
  • Products overview - Feature-focused organization

Measurable outcomes​

User experience metrics​

  • Average session duration increased 45% after restructuring
  • Pages per session increased 35% with improved content discovery
  • Tutorial completion rates improved 50% with clearer information flow
  • Search success rates improved 40% with better content categorization

Business impact metrics​

  • Documentation-to-trial conversion improved 30% with optimized funnel
  • Feature adoption rates increased 25% through strategic feature placement
  • Support ticket volume decreased 35% with more findable information
  • Developer satisfaction scores improved significantly in quarterly surveys

The key insight: Information architecture isn't just about organizing content - it's about architecting the developer's journey from curiosity to successful implementation to long-term value realization. Every structural decision impacts both user experience and business outcomes.
